# Courier Marketplace — UX Specification (Phase 4)

## 1. Information Architecture

**Customer app:** Home (quote entry) → Order Builder (pickup/drop-off/package/service level) → Quote Review → Payment → Live Tracking → Order History → Profile/Saved Addresses → Business Account (if applicable).

**Driver app:** Home (online/offline toggle + offers) → Active Route (stop sequence) → Pickup Verification → Delivery Verification → Earnings → Documents/Onboarding status → Profile.

**Admin portal:** Live Ops Map → Orders (all statuses, filterable) → Route Batches → Drivers (roster, documents, approvals) → Pricing (plans/rules/versions) → Zones/Service Areas → Claims/Disputes → Reports/KPIs → Users/Roles (staff) → Audit Log.

## 2. Screen Inventory (core, MVP)

**Customer app (14):** Sign up/Verify, Home/Quote entry, Package details, Service-level comparison, Quote breakdown, Payment method, Order confirmation, Live tracking, Delivery-complete/POD view, Order history, Order detail, Rate driver, Report a problem, Profile/Saved addresses.

**Driver app (13):** Apply/Onboarding steps, Document upload, Application status (pending/approved/rejected), Online/offline home, Offer detail (single), Offer detail (grouped), Active route/stop list, Navigate-to-stop, Pickup verification flow, Delivery verification flow, Failed-delivery flow, Earnings/Payouts, Profile.

**Admin portal (12):** Live ops map, Orders list/detail, Route-batch detail (with grouping rationale), Driver roster, Driver detail/document review, Pricing plans list, Pricing rule editor (with test mode), Zones/service-areas editor, Claims/disputes queue, Claim detail, Reports/KPI dashboard, Audit log viewer.

## 3. Navigation Model
- Customer/Driver apps: bottom tab bar (3–4 primary destinations) + stack navigation within each tab; live tracking and active-route screens are "locked" full-screen states during an active order (minimal chrome, max information).
- Admin portal: persistent left sidebar (role-filtered), top bar for market/zone selector and search, map is the default landing view for dispatchers specifically (ops/finance land on Reports).

## 5. Design-System Recommendations
- Shared token set (color, spacing, type) across customer/driver/admin, with role-specific accent (e.g., customer = brand primary, driver = a distinct "on-shift" color for active-route mode to reduce misreads while driving).
- High-contrast, large-tap-target components for driver app (used one-handed, often outdoors/in-vehicle).
- Use unambiguous action verbs everywhere, per your instruction — "Confirm pickup," "Complete delivery," never generic "Submit"/"Sign in/out" where a more specific verb exists.
- Map components share one abstraction so the mapping provider can be swapped without touching UI code (per architecture doc §1 abstraction requirement... consistent with routing-provider abstraction).

## 6. Error, Empty, Loading, Offline & Permission States (patterns, apply everywhere)

| State | Pattern |
|---|---|
| **Loading** | Skeleton screens for list/detail views; spinner only for sub-second actions (quote calc, payment) |
| **Empty** | Order history empty → "No deliveries yet" + CTA to request one; driver offer feed empty → "No offers nearby right now" with online-status reminder |
| **Error (recoverable)** | Inline message + retry action, never a dead-end screen (e.g., quote calc fails → "Couldn't get a quote — retry" not a blank screen) |
| **Error (blocking)** | e.g., GPS radius fail on pickup → explicit reason shown ("You're 340m from pickup — get closer to confirm") with a manual dispatcher-escalation path if repeatedly failing |
| **Offline (driver app)** | Banner: "Offline — actions will sync when reconnected," queued actions show a pending indicator until confirmed synced; app blocks nothing that's safe to queue (pickup/delivery evidence) but blocks anything requiring a live server decision (accepting a new offer) |
| **Permission denial** | Camera/location permission declined → explain exactly why it's required for this specific action ("We need your location to confirm you're at the pickup") with a direct link to system settings, not just a dead button |
